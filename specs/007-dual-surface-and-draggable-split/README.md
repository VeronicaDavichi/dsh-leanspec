# 双形态面板（弹窗 / 右栏标签）+ 可拖拽分栏

**类型**: 设计驱动（design-first）
**状态**: complete（2026-10-08 结项 ✅）
**优先级**: medium
**创建日期**: 2026-10-08

---

## 概述

LeanSpec 面板目前只有一种形态：锚在会话页眉 LeanSpec 按钮下方的 **920 × 560 弹窗**，目录栏固定 280px。窗口一窄就难受 —— 实测视口 1024×768 时正文可用宽只剩 551px，800×600 时只剩 **358px**，四列表格已经开始内部横滚。

本 Spec 把同一份内容做成**两个出口**：

1. **宽裕时** → 弹窗，放大到 **1040 × 640**（原 920 × 560）
2. **局促时** → 宿主**右栏标签页**（Preview / Review 同类），标签 chrome 与关闭 × 由宿主 dock 提供
3. 两个形态**共享同一份状态**（选中文件、预览/编辑模式、未保存草稿、分栏比例、目录展开层级）；弹窗可以**单向**切到右栏标签，标签的关闭交给宿主 ×
4. 两个形态里**目录 / 正文之间的分隔条都能拖**，比例记住

```
                       ┌─ 宽 ≥1088 且 高 ≥712 ──►  popup 1040×640 ─┐
点页眉 LeanSpec 按钮 ──┤                                              ├─[单向：在右栏打开 ⧉]
                       └─ 否则 ────────────────►  右栏标签页      ─┘
        （判定读 window.innerWidth / innerHeight + 按钮自身矩形，**实时求值**；
          标签已经开着时按钮只聚焦它，绝不再开弹窗）

   弹窗形态                                右栏标签形态
   ┌───────────────────────┐              ┌──────────┬─────────────────┐
   │ 目录 │◄──拖──►│  正文  │              │          │[Preview][LeanSpec ×]│
   │ 280  │        │        │              │   聊天   │ 目录│◄─拖─►│正文 │
   └───────────────────────┘              └──────────┴─────────────────┘
```

## 功能说明

### 双形态面板（弹窗 / 右栏标签）

同一个 `LeanspecViewer`、同一份 store 状态，两种外壳：

| | 弹窗 | 右栏标签 |
|---|---|---|
| 何时出现 | 页眉按钮按 `decideSurface` 判定为宽裕（或点击时判定为宽裕） | 判定为局促，或用户在弹窗里点「右栏 ⧉」 |
| 尺寸 | `1040 × 640`（`min()` 上限见下） | 填满宿主给的分栏（`width/height: 100%`） |
| 锚点 | 页眉按钮下方（`--anchor` 行内注入，CSS 兜底 `48px`） | 宿主标签页 chrome 由宿主提供 |
| 切换入口 | 「右栏 ⧉」（目录栏标题行右侧，**单向**） | **无**（关闭交给宿主 ×） |
| 关闭 | 点页眉按钮 / Esc / 点外面 | 宿主标签的 × |

**单向 + 聚焦**：标签活着时页眉按钮只**聚焦**它（`openTab` 用宿主默认 `revealIfOpened`，宿主去重），不会在标签旁边再开一个弹窗（REQ-3.3）。自动方向只有「弹窗 → 标签」（窗口变窄），反方向不做 —— 那需要插件主动关掉用户的标签。

**实时跟随**：`resize` 经 150ms 节流后重新判定，只有在结论**变化**时才切形态；拖分隔条期间推迟到拖动结束；右栏未挂载时先给一句提示再等；手动选过的那一次会 `pinned`（直到面板关闭/重开）。

### 为什么是 1088 / 712

```
宽：1040（弹窗宽） + 2 × 24（左右各 24px 边距）        = 1088
高：640（弹窗高）  + 48（锚点兜底：按钮 ~40 + 8 间隙）
                    + 24（底边留 24px）                = 712
```

- **24px** 是设计里假定的页眉右内边距与底边余量；**48px** 是锚点兜底（真机页眉高度**尚未量测**，T0.3 未完成）。
- 这两个数是**舒适阈值**，不是安全属性：CSS 自己带视口上限 —— `width: min(1040px, calc(100vw - 48px))`、`height: min(640px, calc(100vh - var(--anchor, 48px) - 24px))` —— 所以锚点再大也只是让弹窗矮几像素，**不会越界**（REQ-2.2，量测见 tasks.md T3.4）。
- ⚠️ **真机锚点量出来后，`ANCHOR_FALLBACK`（`src/client/surface.ts`）与 CSS 里的 `var(--anchor, 48px)` 必须一起改**，账面的 712/716 也要跟着重算；只改一个会让「判定」和「真实盒模型」错位。`test/surface.test.ts` 与 `test/popover-metrics.test.ts` 会在同一次运行里指出所有需要同步的地方。

### 已知限制（如实记录）

1. **单向**：插件只打开/聚焦标签，从不关闭它 —— 包括窗口变宽裕时也不会把标签换成弹窗（否则等于替用户关东西）。想恢复双向需接回 `close(active().id)`，宿主能力已量测并留档在 design.md §7.1 / §13。
2. **活标签优先**：标签在屏上时页眉按钮只聚焦；此时不存在「弹窗 + 标签」两份面板（REQ-3.3）。
3. **`pinned` 只维持一次会话**：面板关闭/重开后回到自动跟随；pin 由弹窗内「在右栏打开」置位（那是唯一的手动切换入口）。
4. **目录/文件内容不会自动变新**：`/tree` 只在打开、切形态、`projectRoot` 变化时重拉（切形态是后台刷新，不清屏）；没有手动刷新按钮。
5. **唯一未测项**：锚点 / 右内边距真值（T0.3，2026-10-08 用户决定**豁免**不量）—— 运行时 `--anchor` 是实测注入、CSS 自带视口上限，故不影响正确性；其余目视项均已由用户真机验证，见下方「真机验收状态」。

## 冻结决策速览

| 决策点 | 结论 | 理由摘要 |
|--------|------|----------|
| 标签表面 | **只用宿主右栏标签** `sidebar.right.pane.tab`（+ `.title`），**不做**「对话 / 轨迹」那条 `conversation.view` | 用户 2026-10-08 裁定「sidebar 也行」。右栏三个关键点全中：① 有文档明写的编程打开 `ctx.sidebarRight.openTab`（对话条只有“视图自己拿得到”的 `openView` prop）② 标签关闭由宿主 dock 提供（`conversation.view` 的 registerOptions 只有 `id` / `order` / `label`，没有任何关闭能力）③ 天然与聊天并排。详见 design.md §2 |
| 断点 | 宽 **1088** / 高 **712**（**不是** 1040 / 640） | 弹窗 `right:0` 锚在页眉按钮上，实测页眉右内边距 16px → 视口正好 1040 时弹窗左边界 = **−16px 越界**；高度上弹窗顶边 = 按钮下沿 + 8 → 640 高需要视口 ≥700px，定版取 48px 兜底锚点 → 712。实现按按钮矩形现算而非写死，CSS 侧另有 `var(--anchor, 48px)` 兜底首帧。详见 design.md §4 / §5 |
| 弹窗尺寸 | **1040 × 640** | 宽度按用户指定；高度对齐用户给的「长度 640 分界」；真机「目录高度正常」，故不加 `min-height` |
| 形态判定 | **形态 = 宿主尺寸的函数，实时求值**：跨过阈值即切换（守卫：拖动中推迟到拖动结束、右栏未挂载则等待、有活标签则不开弹窗）| 用户 2026-10-08 追问「popup 和右栏不能按宿主大小选择么」→ 实时跟随才是默认语义；状态在共享 store，切换不丢内容 |
| 手动覆盖 | 弹窗内「在右栏打开」= 用户手动选择 → **钉住**该形态，直到面板关闭 / 重开 | 否则自动规则会立刻把手动的选择翻回去。唯一置位点就是那颗按钮（`switchToTab({ pin: true })`）；标签正文挂载**不**清 pin（挂载是宿主动作），关闭/重开才清 |
| 标签 → 弹窗 | **不做（2026-10-08 用户决定）** | 用户：「标签转弹框我觉得没有必要」。因此标签内无任何切换控件、插件不关宿主标签；旧的三级关闭降级（`closeTab` → 注销 seat → 占位）与 `close(tabId)` 探测一并删除（design.md §7.1 留档）。替代语义 = **单向 + 聚焦**：标签活着时页眉按钮只聚焦它（REQ-3.3 同屏唯一实例）|
| 状态 | 模块级**共享 store**（不是两个独立实例） | 否则同一文件两处不同步、编辑草稿互相覆盖；真机 bug「切形态后目录展开合上」就是这个坑，已把 `expanded` 移入 store（design.md §13.4）|
| 同屏约束 | 同一时刻**只允许一个形态存在** | 两个都开会出现两份编辑器，草稿必然打架 |
| 拖拽范围 | 目录 **180–420px**，正文 **≥360px** | 上轮实测：正文 358px 时四列表格开始内部横滚，故 360 作下限 |
| 比例持久化 | `localStorage['leanspec.split']`，非法值回落默认 **280px** | 现目录正好 280px，保持视觉连续 |
| 能力回退 | 无 `ctx.sidebarRight` 或插槽缺失 → 退回纯弹窗 + 按钮置灰提示 | 宿主插槽是**当前版本**的事实，公开契约未承诺 |
| 关闭语义 | 宿主关标签 = 卸载视图；store 状态保留；再点页眉按钮可重开 | 复用宿主 dock 的 ×，不自绘关闭按钮。正文卸载是**唯一**能观测到标签消失的信号，因此挂载/卸载都要写回 store（design.md §13.3）|

## 验收后追加调整（2026-10-08）

| 项 | 结论 |
|----|------|
| 「在右栏打开」的位置 | **搬进目录栏标题行**：与「LeanSpec」同排、在目录栏区域内**靠右对齐**（`LeanspecViewer.headAction` → `.dsh-leanspec-aside-head`）；原全宽切换条改为**只在有原因/失败时**才出现的提示行 |
| 理由（用户原话）| 「在右侧打开是否可以做到和左边目录栏里面的 LeanSpec 字样同行，并在目录栏的区域里靠右对齐」|
| 窄面板保护 | 标题 `min-width: 0` + `text-overflow: ellipsis`：分隔条拉到 180px 下限时**先压标题**，不把按钮挤出目录栏 |
| **不换行**（用户追加，2026-10-08）| 按钮是这一行**唯一不可压缩项**：`.dsh-leanspec-switch` 加 `flex: 0 0 auto` + `white-space: nowrap`；可见文案由 `在右栏打开 ⧉` 精简为 **`右栏 ⧉`**（两字 + 图标），全句移入 `title` 与新增的 `aria-label`。**180px 下限不动** —— 账算过：`28 + ~58 + 8 + ~64 ≈ 158px` 放得下；真凶是按钮缺 `nowrap`（中文在**字间**断行、整行变高）|
| 影响面 | 弹窗 ✅；右栏标签正文**不传 `headAction`**，因此不受影响（它本来就没有切换控件）✅；切换逻辑与 store **零改动** ✅ |
| 证据 | `test/tab-views.test.ts`（按钮作为 viewer 的 `headAction` 传递、只渲染一次、可见文字 ≤4 字且带全句 `aria-label`）+ `test/styles.test.ts`（header row 为 `space-between`、标题可省略、按钮 `nowrap` 且不收缩）；`npm test` **271 / 271 / fail 0**、typecheck 干净、`lib/client.js` 135.8kb |
| 真机 | ⏳ **待用户复验**（步骤见 tasks.md T5.1 / T5.2）|
| 若仍嫌窄 | 抬高下限只需改 `surface.ts` 的 `SPLIT_MIN`（180 → 200 / 220），但**必须同步**改 design.md T1.2 冻结值、`test/surface.test.ts` 的边界与文档里的「180–420px」表述 —— **等用户拍板** |
