# 弹窗可调长宽（右上角单手柄，全局生效）

**类型**: 需求驱动（requirements-first）
**状态**: in-progress（2026-11-26 开工）
**优先级**: medium
**创建日期**: 2026-11-26
**提出人**: 用户（2026-11-26 原话：「浮动框我想可以编辑长宽，并且对所有会话生效」）

---

## 概述

弹窗（`.dsh-leanspec-popover`）现在的尺寸是**两处写死的常量**：`surface.ts` 的 `PANEL_WIDTH = 1040` / `PANEL_HEIGHT = 640` 决定「窗口够不够大」，`styles.ts` 的 `width: min(1040px, …)` / `height: min(640px, …)` 决定它实际多宽多高。用户无法把它调小去看旁边的内容，也无法在宽屏上把它调大。

本 Spec 让弹窗**像桌面窗口一样可拖拽调整长宽**：

1. 弹窗**右下角一个对角手柄**，拖动同时改宽和高
2. 尺寸**记住**，并且**对所有会话 / 所有项目共用一份**（浏览器 `localStorage`，不按会话或工作区分片）
3. 形态判定（弹窗 vs 右栏标签）改用**你设定的尺寸**：调小之后，原本只能开右栏标签的窄窗口也能用弹窗
4. 双击手柄复位到默认的 1040×640
5. 右栏标签**不跟随**：标签宽度由宿主分栏决定，插件不接管

阈值、上限与不变的边界见 [requirements.md](./requirements.md)，实现方案见 [design.md](./design.md)，任务见 [tasks.md](./tasks.md)。

## 冻结决策（2026-11-26）

| # | 决策 | 理由 |
|---|------|------|
| D-1 | **右下角单个对角手柄**，不做四角/四边 | 一处命中区、一套边界处理，改动面最小；2D 调整一个手柄就够 |
| D-2 | 最小 **600 × 420** | 600 仍能放下 180px 目录 + 360px 正文（含分隔条与边框余量）；420 够目录树与工具栏，再矮树就没法用了 |
| D-3 | 最大 = **视口上限**，不设第二套绝对值 | `100vw - 48`、`100vh - anchor - 24` 已经由 CSS 兜底，再叠一层魔法数只会互相矛盾 |
| D-4 | 形态判定用**用户设定的尺寸** | 尺寸是「弹窗占多大」的唯一真相；判定与观感一致，否则缩小毫无意义 |
| D-5 | 尺寸**全局一份**，`localStorage['leanspec.panel']` | 用户明确要求「对所有会话生效」；与「分栏比例」不同，它不是某一棵树的属性 |
| D-6 | 双击手柄复位 **1040 × 640** | 与 007 的默认值一致，用户不需要记住「默认是多少」 |
| D-7 | 右栏标签**不跟随**弹窗尺寸 | 标签的宽度由宿主 dock 分栏控制，插件没有、也不该有写入口 |
| D-8 | 未调过的用户**行为完全不变** | 默认 1040×640 代入判定，结果与 007 逐位相同（回归由测试钉死） |

## 硬规则偏离说明

- **E2E 覆盖**：本仓库**没有 `e2e/` 目录、没有 `harness/` 脚本**，007 已记录过同一豁免（「测试的问题我来，肉眼看」）。本 Spec 沿用该豁免：验证 = `node --test`（纯逻辑 + 结构断言 + CSS 量测）+ `pnpm build` + `pnpm typecheck`，浏览器手势由用户目视确认。**这是显式记录，不是静默跳过。**
- **UI 原型**：本 Spec 无 `assets/prototype/`，无视觉对照任务。
- **docs/ 全树**：仓库无 `docs/`，见 requirements.md §0。

---

## 非目标

- 不改右栏标签的尺寸或布局
- 不新增「把弹窗拖到屏幕任意位置」的浮窗能力（仍是锚在页眉按钮下方的弹窗）
- 不做多套命名尺寸 / 预设尺寸菜单
- 不把尺寸写进项目文件或带到别的机器（只用本机 `localStorage`）
